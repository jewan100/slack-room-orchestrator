# slack-room-orchestrator 🐾

택배와 소포가 함께 운영하는 Slack 기반 AI 회의실 오케스트레이터.

## 캐릭터 설정
- **택배 (OpenClaw 메인 에이전트)**: 검정고양이, 소포의 형님, 총괄 오케스트레이터
- **소포 (워커 에이전트들)**: 하얀고양이들, 병렬 실행/분석/검증 담당

## 역할 구조
- **택배**: 지시 해석, 회의 진행, 결정 정리, 리마인드/운영 관리
- **소포들**: 아이디어 발산, 반박, 리스크 점검, 코드 작업 병렬 수행

## 목표
- 형은 결정에 집중
- 실행/추적/정리는 택배+소포가 자동 처리

## 기본 흐름
1. `/room start <topic>`: 준비 스레드에서 컨텍스트 정리
2. `/room launch`: 실행 스레드에서 소포 워커 토론 시작
3. `/room decide <A|B|C>`: 최종 결정 확정 + 액션/리마인드 생성

## 개발 원칙 (요약)
- 가독성 최우선 (짧은 코드보다 읽기 쉬운 코드)
- 네이밍 엄격 (이름만 보고 역할 파악 가능해야 함)
- SRP 강제 (함수/클래스 1책임)
- 브랜치 전략: `develop` 기본, `feat/*`로 작업, `main` 직접 작업 금지
- 브랜치명 규칙: 영어/소문자/하이픈
- PR/커밋 메시지: 한글 우선, PR 본문은 상세 작성
- 리뷰: Copilot 1차 + Codex 최종 통합 리뷰
- CI(lint/typecheck/test) 통과 전 머지 금지
- 기술 도입 시 사전 검증 필수, `latest` 금지
- 확장성/이식성 우선 (로컬→N100 동일 동작 목표)
