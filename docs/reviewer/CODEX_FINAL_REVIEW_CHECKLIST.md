# CODEX_FINAL_REVIEW_CHECKLIST.md

## 목적
머지 직전, Codex가 전체 변경을 최종 검증한다.

## 체크 항목

### 1) 기능 정합성
- [ ] 요구사항 대비 누락 기능 없음
- [ ] start/launch/status/summary/decide 흐름 연결 정상

### 2) 아키텍처/책임 분리
- [ ] SRP 위반 없음
- [ ] service/validator/adapter/repository 경계 준수
- [ ] 외부 연동은 adapter로 분리됨

### 3) 코드 품질
- [ ] 네이밍 규칙 준수(역할 명확)
- [ ] 가독성/포맷팅 일관성
- [ ] any 사용 없음
- [ ] 독자 친화형+맥락형 주석 정책 준수(모듈/핵심 함수 설명, 비자명 의도/함정/트레이드오프 설명, 불필요 반복 주석 없음)
- [ ] `await`/외부 I/O/상태 전이/DB write-read 구간 주석에 목적/이유/영향이 설명됨
- [ ] 주석 문체 규칙 준수(동사 문장만 `~다.`, 명사 문장은 `~다.` 미사용)
- [ ] 사용자 노출 문구/에러 문구 중앙 관리(분산 하드코딩 없음)
- [ ] 함수 복잡도/함수 길이 상한 준수

### 4) 안정성/에러 처리
- [ ] 에러 응답 형식 통일
- [ ] 에러코드 누락 없음
- [ ] 예외 처리 일관성

### 5) 보안/로그
- [ ] 민감정보 로그 노출 없음
- [ ] requestId/elapsedMs 등 추적 필드 존재

### 6) 테스트/CI
- [ ] lint 통과
- [ ] typecheck 통과
- [ ] 테스트(단위/통합) 통과
- [ ] 비동기 안전성 점검(no-floating-promises 위반 없음)

### 7) 문서/추적
- [ ] PR 본문 한글 상세 작성
- [ ] CHANGELOG/ADR/DECISION_LOG 반영
- [ ] 후속 TODO/리스크 문서화
- [ ] 기능 브랜치 기반 작업인지 확인(사용자 승인 없는 `develop` 직접 커밋/푸시 없음)

## 결과 분류
- PASS: 즉시 머지 가능
- CONDITIONAL: 경미 수정 후 머지
- BLOCK: 머지 금지, 수정 필수
